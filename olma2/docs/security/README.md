## באיזו רמת אבטחה מדובר — לבירור עם עו״ד

ההנחה שבה נכתבו המסמכים: **"מאגר המנוהל בידי יחיד"** (התוספת הראשונה
לתקנות) — המפעיל, מירון דדוש, הוא האדם היחיד שיש לו גישה למאגר. אם עו״ד
יקבע שהמאגר אינו עומד בתנאי המסלול הזה (למשל בגלל מספר נושאי המידע או
בגלל שהמאגר כולל מידע רפואי שמשתמשים בוחרים לשתף), הרמה הסבירה היא
**בינונית**, ואז נדרשים בנוסף בין היתר: סקר/בדיקה תקופתית של הנוהל, תיעוד
מסודר יותר של אירועים ושל גישות, ומינוי ממונה או מי שמחליפו. המסמכים
כתובים כך שיספיקו גם לרמה הבינונית ככל האפשר; הפערים הידועים מסומנים בהם
"לבירור עם עו״ד".

## מקור האמת

המסמכים נכתבו מתוך הקוד שבמאגר הזה ומבדיקה של השרת החי ב-2026-09-28. כל
טענה בהם מפנה לקובץ שמבצע אותה. **אם המסמך והמערכת סותרים — המערכת
קובעת, והמסמך מתוקן.** עדכון כאן אינו משנה שום התנהגות.

## מתי לבדוק מחדש

- **פעם בשנה לפחות** (תקנה 2(ג) דורשת בדיקה שנתית שהמידע במאגר אינו רחב
  מהנדרש למטרותיו; תקנה 4 דורשת עדכון הנוהל). הבדיקה הבאה: **עד 2027-09-28**.
- **בכל שינוי מהותי**, ובכלל זה: ספק חדש שמקבל מידע אישי (מודל, שירות קול,
  אחסון); סוג מידע חדש שנאסף (עמודה או טבלה חדשה בנתוני משתמש); העברת השרת
  או הגיבוי למדינה אחרת; אדם נוסף שמקבל גישה למאגר; אירוע אבטחה.
- בכל בדיקה: לעדכן את התאריך למעלה, ולרשום בסעיף "היסטוריית בדיקות" בסוף
  `security-procedure.md` מה נבדק ומה שונה.
